Etapa 3 · Reglas de integración

Reglas de homologación y correspondencia

Definición de las reglas utilizadas para estandarizar, validar y establecer correspondencias entre los datos de siniestros viales y los vehículos involucrados.

01

Propósito de las reglas

Las reglas de integración establecen las condiciones que deben cumplir los registros antes de ser relacionados entre las dos fuentes de datos.

Su finalidad es reducir correspondencias incorrectas, establecer criterios uniformes para los campos geográficos y temporales y definir cómo se deben tratar los registros que no presentan una coincidencia suficiente.

02

Reglas generales de integración

R-01

Identificación de fuentes

Cada registro debe conservar su procedencia para poder identificar si proviene del dataset de siniestros o del dataset de vehículos.

R-02

Conservación de identificadores

Los identificadores originales de cada fuente deben conservarse como referencia y no deben utilizarse directamente como claves foráneas entre datasets.

R-03

Homologación geográfica

Los nombres de departamento y municipio deben normalizarse para evitar diferencias de escritura, mayúsculas, espacios y otras variaciones.

R-04

Normalización de fechas

Los campos de fecha deben convertirse a un formato uniforme antes de realizar cualquier comparación entre registros.

03

Reglas de homologación de campos

Durante el diagnóstico se identificaron campos equivalentes entre las fuentes, aunque presentan nombres y estructuras diferentes. Por esta razón, se establece la siguiente correspondencia:

Concepto Siniestros Vehículos Regla aplicada
Fecha fecha_hech fecha_accidente Convertir ambos campos al mismo tipo de fecha antes de realizar la comparación.
Departamento depto_hech departamento_accidente Normalizar texto y comparar utilizando una nomenclatura geográfica uniforme.
Municipio municipio_ municipio_accidente Eliminar diferencias de formato y homologar nombres antes de comparar.
Identificador hechos_id No existe equivalente directo No establecer una relación directa mediante este campo.
04

Reglas de limpieza y estandarización

L-01 · TEXTO

Campos textuales

Aplicar eliminación de espacios innecesarios, conversión a una representación uniforme y revisión de valores vacíos antes de realizar comparaciones.

L-02 · FECHA

Campos temporales

Validar que los valores correspondan a fechas válidas y utilizar una representación temporal común.

L-03 · GEOGRAFÍA

Departamento y municipio

Homologar los nombres geográficos para evitar que diferencias de escritura generen falsos registros sin coincidencia.

L-04 · NULOS

Valores faltantes

Los valores faltantes en los atributos utilizados para establecer correspondencias deben identificarse y evitar que sean utilizados como coincidencias válidas.

05

Criterios de coincidencia entre fuentes

Debido a que las fuentes no comparten una clave primaria común, la integración se basa en atributos disponibles en ambos datasets.

Coincidencia fuerte

Fecha + departamento + municipio coinciden después de aplicar la homologación correspondiente.

Coincidencia parcial

Coincide la fecha junto con departamento o municipio, pero no se dispone de los tres criterios simultáneamente.

Sin coincidencia

No se encuentra una correspondencia suficiente entre los atributos disponibles de ambas fuentes.

06

Regla de validación de correspondencias

Una coincidencia encontrada mediante fecha, departamento y municipio no debe interpretarse automáticamente como la identificación inequívoca del mismo accidente.

Estos atributos permiten establecer una correspondencia candidata, pero debido a la ausencia de una clave compartida, los resultados deben conservar el nivel de coincidencia para diferenciar las relaciones fuertes de las parciales.

Criterio establecido

La integración debe conservar información suficiente para identificar cómo se obtuvo cada correspondencia y evitar presentar como relación exacta una coincidencia que solamente cumple criterios parciales.

07

Flujo de aplicación de las reglas

1. Cargar fuentes Lectura de los archivos de siniestros y vehículos.
→
2. Estandarizar Normalización de fechas y atributos geográficos.
→
3. Comparar Evaluación de los atributos comunes entre registros.
→
4. Clasificar Coincidencia fuerte, parcial o sin coincidencia.
→
5. Integrar Preparación de los registros para el proceso ETL.

09

Reglas preparadas para el proceso SSIS

Las reglas definidas en esta sección sirven como especificación para la siguiente fase del proceso de integración, donde serán implementadas mediante un flujo ETL.

ENTRADA

Fuentes originales

Los archivos CSV de siniestros y vehículos constituyen las fuentes de entrada del proceso.

TRANSFORMACIÓN

Homologación

Se transforman fechas, departamentos y municipios a estructuras comparables.

VALIDACIÓN

Correspondencias

Se aplican los criterios de coincidencia y se clasifica cada posible relación.

SALIDA

Modelo integrado

Los datos preparados pueden ser utilizados por el modelo relacional definido para la integración.

Resultado de la etapa de reglas

Se establecieron las condiciones necesarias para homologar los campos comunes, validar fechas y atributos geográficos, clasificar las correspondencias y preparar la integración de los dos datasets sin asumir la existencia de una clave compartida que no está presente en las fuentes originales.
